# PRD：个人复习教练（Qoder 赛题）

## 1. 背景与痛点

| 痛点 | 现状 |
| --- | --- |
| 资料散、找不回 | 讲义、笔记、错题截图分散在多处，「考试前记得看过但找不到原句」 |
| 复习无闭环 | 看过 ≠ 记住，缺少「学 → 测 → 记住薄弱点 → 下次优先复习」的循环 |
| 进度不连续 | 复习中断后重启，不记得上次学到哪、错在哪，只能从头再来 |

核心思路：**知识检索交给 seekdb，学习记忆交给 PowerContext**，应用本身专注复习流程体验。

## 2. 目标用户

备考学生、准备认证考试的在职人员、需要持续学习的科研/工程人员。

## 3. 产品定位

一句话：导入你的资料 → 随时带着出处提问 → 做复习自测 → 系统记住你的薄弱点 → 第二次打开就知道该复习什么。

## 4. 功能清单（按阶段划分）

### F1 资料导入与索引（阶段 2）
- 用户上传/粘贴 Markdown、TXT 资料；后端按标题/段落切块（带来源：文件名 + 标题 + 序号）。
- 切块写入嵌入式 seekdb（pyseekdb）集合，向量索引 + 元数据（source/title/index）。
- 支持查看已导入资料列表与删除重灌。

### F2 混合检索问答（阶段 2）
- 用户输入问题，后端执行三路检索：
  1. **向量检索**：问题 embedding 与资料块 embedding 的 cosine 相似度；
  2. **关键词过滤**：对检索结果按问题关键词做元数据/文本匹配加权；
  3. **结构化过滤**：支持按来源文件、标题过滤（metadata where 条件）。
- 返回 Top-K 块 + **出处引用**（文件名 / 标题），前端展示为「答案依据」列表。
- 检索时记录日志：每次查询的三路信号与最终排序（提交时作为「技术发挥作用」证据，见 VALIDATION.md 第 4 节）。

### F3 复习自测（阶段 4）
- 基于已导入资料生成复习卡（问句由资料块生成或用户自建）。
- 用户自评：会 / 不会 / 模糊。
- 每次自评产生一条记录：知识点、结果、时间、来源引用。

### F4 学习者记忆与续接（阶段 3 + 4）
- 自评结果、薄弱点归纳、复习偏好（如「每天 20 分钟」「先攻高频考点」）通过 PowerContext `/v1/memory/remember` 写入长期记忆（kind: decision/observation）。
- 每次打开应用调用 `/v1/context/prepare` 取回历史上下文，首页展示「上次复习进度 + 今日推荐复习清单」。
- 薄弱点相关知识点在出题时提高优先级（优先从薄弱点对应的资料来源出题）。

### F5 项目网站（阶段 6，用 Qoder Sites 发布）
网站必备内容：项目简介、解决的问题、核心功能、演示视频或截图、代码仓库链接、体验入口。

## 5. 架构

```
┌─────────────────────────────────────────────────┐
│ 前端（单页 HTML/JS，由 Qoder Sites 托管发布）        │
│  资料导入 / 问答（带出处）/ 复习卡片 / 进度面板       │
└───────────────▲─────────────────────────────────┘
                │ HTTP (REST/JSON)
┌───────────────┴─────────────────────────────────┐
│ 后端 FastAPI（qoder/app/）                        │
│  /api/documents  导入/列表/删除                    │
│  /api/ask        三路混合检索 + 出处引用            │
│  /api/review     出题、自评                        │
│  /api/plan       今日复习计划（读记忆）              │
└──────┬───────────────────────▲──────────────────┘
       │                       │
┌──────▼──────────┐   ┌────────┴──────────────────┐
│ seekdb（嵌入式）  │   │ PowerContext Server        │
│ pyseekdb         │   │ uv tool install            │
│ 资料知识库：       │   │ POST /v1/scopes            │
│  向量+关键词+      │   │ POST /v1/memory/remember   │
│  元数据过滤       │   │ POST /v1/memory/search     │
│                  │   │ POST /v1/context/prepare   │
│ 分工：知识检索     │   │ 分工：学习者记忆/进度/偏好    │
└─────────────────┘   └───────────────────────────┘
```

### 两组件分工（同用两组件时需向评委说明）

- **seekdb（pyseekdb 嵌入式）**：应用的知识底座。所有导入资料切块后建向量索引（HNSW, cosine），查询时「向量相似 + 关键词匹配 + 元数据结构化过滤」三路结合选块，并把命中块及其出处返回给问答与出题环节。
- **PowerContext（本地 Server + HTTP API）**：应用的记忆底座。错误自评、薄弱点、复习偏好写入 Memory；应用重启后通过 context/prepare 取回，实现「跨会话续接复习」。资料本身不入 PowerContext，避免与 seekdb 职责重叠。

## 6. 非功能约束

- 后端运行环境：**Linux x86_64（WSL2 即可）**——pyseekdb wheel 仅提供 Linux 版。
- seekdb 数据库目录必须位于本地文件系统（不要放 `/mnt/c` 等挂载路径）。
- 任何模型/Embedding API Key 只从环境变量读取，不写入代码与仓库；默认提供本地确定性 Embedding 以便无 Key 演示。
- 提交材料不包含真实 Key；演示若用付费 API，用环境变量注入并在 RUNBOOK 注明。

| 评分项 | 本方案对应 |

| 完成度体验 | 导入→问答→自测→计划完整链路 |
