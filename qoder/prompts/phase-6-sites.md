# 阶段 6：Qoder Sites 发布准备

> 前置：阶段 5 全部验证通过。本阶段准备「能被 Qoder Sites 发布」的网站版本 + 网站内容素材。发布动作本身按 `qoder/SITES.md` 在 Qoder 界面操作。

---

请为「复习教练 RecallLoop」准备 Qoder Sites 发布版本。

## 一、可发布站点形态

1. 新增 `qoder/app/static/index.html` 为站点首页（或改造现有单页），包含以下必备板块：
   - **项目简介**：一句话 + 3 行说明；
   - **解决的问题**：资料散、复习无闭环、进度不连续（见 `qoder/PRD.md` 第 1 节）；
   - **核心功能**：资料导入 / 带出处问答 / 复习自测 / 跨会话续接，配阶段 4 的截图；
   - **演示**：截图 3–4 张（问答带出处、自评、跨会话续接），有条件录一段 ≤ 2 分钟演示视频并放链接；
   - **代码仓库链接**：`https://github.com/chaizedong73-arch/PowerContext-bigheart-2026`；
   - **体验入口**：在线 Demo 链接（见下）+ 本地启动指引摘要。
2. 站点要**不依赖后端也能展示**：演示区用静态截图 + 预录内容呈现；「体验入口」提供两种：
   - 在线 Demo（若 Qoder Sites 支持托管应用的运行版，按 SITES.md 实际操作为准）；
   - 本地部署指引（链接到仓库 RUNBOOK）。
3. 注意：后端依赖 WSL2/Linux（pyseekdb wheel 限制），如果 Sites 托管的是纯静态页面，就把「在线体验」做成**预置数据的演示模式**：前端内置一份示例资料与示例问答记录，按钮可点、流程可走通，并在页面显著标注「演示模式，完整功能见本地部署」。这样评委无需部署即可体验交互。

## 二、材料归集

1. 新建 `qoder/site-material/` 目录，归集：
   - `screenshots/`：阶段 4、5 的截图（问答、自评、续接、检索日志、记忆日志）；
   - `demo-video.md`：演示视频链接与分镜说明；
   - `qoder-log/`：Qoder 对话截图（每阶段至少 1 张）与 Qoder 账号 UID 的记录方式（UID 不要写进仓库，提交时单独填写）。
2. 站点页脚放：项目仓库链接、「基于 OceanBase seekdb 与 PowerContext 构建」、Qoder Sites 徽标（如平台提供）。

## 三、自查清单

- [ ] 首页包含六项必备内容（简介/问题/功能/演示/仓库/体验入口）；
- [ ] 演示模式无 Key 可走通；
- [ ] 仓库内无任何真实 API Key（`git grep -iE "sk-|api[_-]?key\s*=\s*['\"]"` 自查）；
- [ ] `site-material/` 里的截图均为本应用真实运行截图。

完成后输出：站点首页预览方式、material 目录清单、自查结果。
